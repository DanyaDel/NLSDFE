# 🌀 SDF Engine (NLSDFE) - v1.5

**SDF Engine** — игровой движок и редактор на **Signed Distance Fields (SDF)**. Объекты здесь — не полигоны, а чистая математика, которую видеокарта считает в реальном времени. Вокруг рендера собрано всё, что нужно для игры: редактор сцен, физика, собственный скриптовый язык, звук и экспорт в отдельное приложение.

## 🚀 Основные фишки

*   **Vulkan Compute Renderer:** вся отрисовка идёт в compute-шейдере. Хватает Vulkan 1.0 без необязательных фич, так что движок стартует и на встроенной графике.
*   **CSG Operations:** объединение, вычитание, пересечение и плавное «слипание» объектов.
*   **Шесть форм:** сфера, бокс, цилиндр, тор, капсула, конус; плюс импорт полигональных мешей (`.obj`).
*   **Режимы редактора:** Model Editor (SDF-моделлер), Scene Editor (сборка уровня), UV Editor (развёртка мешей), Script Editor (встроенная среда для скриптов).
*   **Компоненты:** к объекту в инспекторе цепляются Collider, Rigid Body, Character Controller, Audio Source, Script, Behavior.
*   **Физика:** твёрдые тела на SDF-коллайдерах — отскоки, трение, стопки, триггеры.
*   **Язык NLS:** свой типизированный скриптовый язык, компилируется в байткод.
*   **Визуальный скриптинг:** граф узлов, который компилируется в тот же NLS; любая функция движка доступна узлом.
*   **SDF ⇄ Mesh:** SDF-модель превращается в полигональный меш, а меш — в воксельное SDF, с которым работают CSG и физика.
*   **Связка с Blender:** объект открывается в настоящем Blender, Ctrl+S там — и правки уже в движке.
*   **Игровые сервисы для скриптов:** интерфейс поверх игры (текст, полоски, кнопки), плавные переходы, сохранения, смена уровней, геймпад, пауза и замедление времени.
*   **Префабы, анимация, частицы, редактор интерфейса:** объект с компонентами сохраняется как префаб и создаётся скриптом; ключевые кадры и частицы настраиваются в инспекторе; экраны меню и HUD собираются мышью.
*   **Play Mode (F5):** сцена запускается прямо в редакторе, вид — через камеру сцены.
*   **Экспорт игры:** отдельный плеер, сцена и скомпилированные скрипты в одной папке.
*   **Для слабого железа:** отсечение объектов по лучу, рендер по требованию, динамическое разрешение, пресеты качества от Potato до Ultra.

## ⚙️ Как собрать проект

### Требования
1.  Драйвер с поддержкой **Vulkan** и `glslc` (пакет `shaderc` в Arch, Vulkan SDK в Windows).
2.  Компилятор C++17 и **CMake** 3.20+.
3.  Для диалогов файлов в Linux — `zenity` или `kdialog`.

Остальные зависимости (GLFW, GLM, ImGui, VMA, spdlog, miniaudio) CMake скачает сам.

### Linux
```bash
git clone https://github.com/DanyaDel/NLSDFE.git
cd NLSDFE
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/SDF_Engine
```

### Windows
```bash
cmake -S . -B build
cmake --build build --config Release
```

### Сборка под Windows из Linux
Нужен MinGW-w64 (`x86_64-w64-mingw32-g++`) и `glslc`; Vulkan SDK не нужен — библиотека импорта для `vulkan-1.dll` делается из `cmake/vulkan-1.def`.
```bash
cmake -S . -B build-win -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build-win
```
В `build-win/` появятся `SDF_Engine.exe`, `NLSDFE_Player.exe`, `nls_tests.exe` и шейдеры `.spv`. Рантайм MinGW вшит статически, из внешних DLL нужен только `vulkan-1.dll` (ставится с драйвером видеокарты). Проверка через wine: `wine build-win/nls_tests.exe`, `wine build-win/NLSDFE_Player.exe --help`. Иконка и сведения о версии вшиваются в оба `.exe` из `assets/windows/nlsdfe.rc`, а `NLSDFE_Player.exe` собирается под подсистему GUI — игра запускается без окна консоли (при запуске из cmd вывод всё равно идёт в консоль родителя).

Шейдеры компилируются при сборке и кладутся рядом с исполняемыми файлами. Тесты: `./build/nls_tests`.

## 🧭 Интерфейс

Сверху — меню **File, Edit, Render, Window, Help**. Под ним — панель режимов:

| Режим | Для чего |
|---|---|
| **Model Editor** | Собрать модель из SDF-примитивов и сохранить в ассеты проекта |
| **Scene Editor** | Собрать уровень, навесить компоненты, запустить Play |
| **UV Editor** | Развёртка импортированных мешей с шахматкой для проверки |
| **UI Editor** | Экраны игрового интерфейса: текст, панели, полоски и кнопки расставляются мышью на холсте |
| **Script Editor** | Скрипты NLS текстом или графом узлов; ошибки видны сразу, справочник API или палитра узлов — справа |

Импорт (меш, модель, скрипт, звук) и экспорт (игра, скриншот) — в меню **File**. Проект — это папка с `assets/`, `scenes/`, `scripts/` и `ui/`. Для знакомства: **File → Load Demo Scene**, затем **F5**.

### SDF ⇄ Mesh

**Object → Convert to Mesh** превращает выделенные SDF-объекты (вместе с их дочерними SDF-частями) в один полигональный меш: CSG сохраняется, цвета материалов переходят в цвета вершин, UV раскладываются автоматически. Меш пишется в `assets/meshes/` проекта.

**Object → Convert to SDF Volume** запекает меш в воксельную сетку расстояний (32³–128³). Получается обычный SDF-объект: работает плавное слияние с другими формами, вычитание, физика. Меш должен быть замкнутым — иначе внутренность определяется неверно.

### Связка с Blender

**Object → Edit in Blender** (в Model Editor — кнопка **Edit in Blender** на панели) открывает объект в Blender:

*   SDF-модель приходит как набор примитивов. В боковой панели **N → NLSDFE** у каждого — форма, размер, операция CSG и сглаживание; вычитание и пересечение показаны каркасом. Там же **Add SDF Primitive**. Цвет — Base Color материала.
*   Меш приходит как есть, со всем инструментарием Blender.
*   **Ctrl+S в Blender** отправляет изменения в движок — редактор подхватывает их сам. Добавленные, удалённые и перемещённые объекты переносятся, всё откатывается одним Ctrl+Z.

Путь к Blender — в **Edit → Preferences → Editor** (по умолчанию `blender` из `PATH`). Объекты Blender, которые не являются примитивами движка, в SDF-модель не попадают.

### Визуальные скрипты

В Script Editor кнопка **New visual script** создаёт граф (`.nlsg`). Правый клик по холсту — добавить узел, перетаскивание от пина к пину — связь, Delete — удалить. Узлы событий (On Start, On Update, On Collide…), потока (Branch, Sequence, For Loop), переменные, свойства объектов, операторы и все функции движка. Неподключённые входы задаются прямо в узле; неподключённый «Target» означает сам объект. На вкладке **Generated NLS** виден код, в который превращается граф. Граф вешается на объект компонентом Script так же, как текстовый скрипт.

### Редактор

*   Границы панелей тянутся мышью; размеры запоминаются.
*   Нижняя панель — вкладки **Assets**, **Timeline** (дорожки всех анимированных объектов, общий курсор времени, Play) и **Console** (вывод скриптов; новые ошибки помечают вкладку).
*   Из **Assets** модели и префабы перетаскиваются во вьюпорт и встают в точку под курсором; звуки и скрипты бросаются на объект.
*   Ошибки скриптов во время Play Mode всплывают в углу экрана.
*   Масштаб интерфейса — **Edit → Preferences → Editor → Interface scale** (после перезапуска).

### Компоненты

Выделите объект и нажмите **Add Component** в инспекторе:

| Компонент | Что делает |
|---|---|
| **Collider** | Чем объект сталкивается: своей формой, боксом, сферой или капсулой. «Is trigger» превращает его в зону, которая шлёт события |
| **Rigid Body** | Объект падает, отскакивает и толкается |
| **Character Controller** | Управление с клавиатуры и мыши: WASD, Shift, пробел. Камера внутри даёт вид от первого лица |
| **Audio Source** | Звук, в том числе объёмный |
| **Script** | Скрипт NLS; его переменные правятся тут же |
| **Behavior** | Готовое вращение или движение туда-обратно без скрипта |
| **Animation** | Ключевые кадры положения, поворота и масштаба: выставить время на дорожке, поставить объект в позу, нажать Add Key. Preview проигрывает прямо в редакторе |
| **Particles** | Источник частиц: поток или залпы по команде скрипта, цвет и размер от рождения до исчезновения, гравитация, отскок от геометрии |

Play Mode смотрит через первую активную **камеру** сцены (Add → Camera).

### Игровые сервисы

Всё ниже доступно и в текстовых скриптах, и узлами в графе.

| Что | Функции |
|---|---|
| **Интерфейс** | `ui.text(текст, x, y, размер, цвет)`, `ui.bar(x, y, w, h, заполнение, цвет)`, `ui.rect(...)`, `ui.button(текст, x, y, w, h)` — возвращает `true` в кадр щелчка. Координаты — в долях экрана (0..1); вызывать каждый кадр в `on update` |
| **Переходы** | `obj.moveTo(точка, секунды)`, `rotateTo`, `scaleTo`, `colorTo`, `obj.isMoving()` |
| **Ориентация** | `obj.lookAt(точка)`, `obj.forward()`, `obj.worldPosition()` |
| **Сохранения** | `save.setFloat / setInt / setString(ключ, значение)`, `save.getFloat / getInt / getString(ключ, по умолчанию)`, `save.has`, `save.remove`, `save.clear`, `save.flush`. Файл `save.dat` лежит в папке проекта (у готовой игры — рядом с ней) и пишется при выходе |
| **Экраны из UI Editor** | `ui.show("menu")`, `ui.hide`, `ui.isShown`, `ui.clicked("menu", "play")`, `ui.setText / setValue / setColor / setVisible(экран, элемент, значение)`. Для меню при обзоре мышью — `input.showCursor(true)` |
| **Создание и удаление** | `scene.spawn(obj)` — копия вместе с потомками, `scene.instantiate("enemy", точка)` — префаб из `assets/prefabs/`, `obj.destroy()`, `obj.isAlive()`, `obj.child("имя")`. Места удалённых объектов используются повторно, так что пули и враги не упираются в лимит узлов |
| **Частицы** | `obj.emit(количество)`, `obj.emitting = true / false` |
| **Анимация** | `obj.playAnimation()`, `resumeAnimation()`, `stopAnimation()`, `isAnimating()`, `obj.animationTime`, `obj.animationSpeed` |
| **Сообщения** | `obj.send("damage", 10.0)`, `scene.broadcast("pause", 1.0)`; у получателя — `on message(name: string, value: float) { ... }`. Доставляются в конце того же кадра |
| **Поиск пути** | `obj.navigateTo(точка, скорость)` — объект сам идёт в обход препятствий; `obj.stopNavigation()`, `obj.isNavigating()`, `obj.pathDistance(точка)` (−1, если дойти нельзя) |
| **Действия ввода** | `input.action("jump")`, `input.actionPressed("fire")`; готовые: `forward`, `back`, `left`, `right`, `jump`, `run`, `fire`, `use` — ими же ходит Character Controller. Свои: `input.define("dash", "q")`. Переназначение: `input.bind("jump", input.lastKey())` — сохраняется вместе с игрой. Кнопки геймпада называются `pad0`…`pad14` |
| **Музыка и громкость** | `audio.playMusic("assets/sounds/theme.mp3", 0.8)` — не прерывается при смене уровня; `audio.stopMusic()`, `audio.setMusicVolume(x)`, `audio.setSoundVolume(x)` |
| **Уровни** | `scene.load("level2")` — сцена из `scenes/`, `scene.restart()`, `game.quit()` |
| **Ввод** | `input.axis("horizontal" / "vertical")` — клавиши и левый стик; `input.mouseX/Y`, `input.mouseDX/DY`; `input.padAxis(0..5)`, `input.padDown(0..14)`, `input.padPressed(...)` |
| **Время** | `time.setScale(0)` — пауза (интерфейс и ввод продолжают работать), `time.every(секунды)` — `true` раз в интервал |

```
var hp: float = 1.0
on update(dt: float) {
    ui.bar(0.03, 0.04, 0.25, 0.03, hp, vec3(0.9, 0.2, 0.2))
    ui.text("Best: " + str(save.getInt("best", 0)), 0.03, 0.09, 22.0, vec3(1, 1, 1))
    if hp <= 0.0 and ui.button("Restart", 0.4, 0.45, 0.2, 0.08) { scene.restart() }
}
```

**Префаб** делается так: выделить объект, **Object → Save as Prefab** — он вместе с потомками и компонентами запишется в `assets/prefabs/<имя>.nos`.

Экспорт игры кладёт рядом все уровни из `scenes/`, экраны из `ui/`, префабы, звуки и скрипты проекта, так что `scene.load`, `ui.show` и `scene.instantiate` работают и в готовой игре. Меши других уровней и префабов копируются рядом с ними.

Ограничения: частицы рисуются поверх кадра кружками: скрываются за геометрией, с галочкой «Lit by the sun» темнеют в тени, но сами теней не отбрасывают; путь ищется в горизонтальной плоскости на высоте объекта (этажи и лестницы не учитываются), движущиеся тела препятствиями не считаются; поворот в анимации интерполируется по углам Эйлера; после `destroy()` старая ссылка на объект может указать на новый объект, занявший его место, — проверяйте `isAlive()` сразу, а не через несколько кадров.

## 📜 Язык NLS

Скрипт — файл `.nls` в папке `scripts/` проекта. Он вешается на объект компонентом Script; `self` — этот объект.

```
var speed: float = 90.0        // видно и правится в инспекторе
var target: node

on start() {
    log("hello from " + self.name)
}

on update(dt: float) {
    self.rotation.y += speed * dt
    if target != null and input.pressed("e") and self.distanceTo(target) < 3.0 {
        target.applyImpulse(vec3(0, 5, 0))
    }
}

on collide(other: node) {
    self.color = vec3(random(), random(), random())
    self.playSound()
}

func square(x: float) -> float { return x * x }
```

*   **Типы:** `float`, `int`, `bool`, `vec3`, `string`, `node`. `int` сам превращается во `float`, обратно — `int(x)`.
*   **События:** `start()`, `update(dt)`, `fixedUpdate(dt)`, `collide(other)`, `triggerEnter(other)`, `triggerExit(other)`.
*   **Управление:** `if / else`, `while`, `for i in 0..10`, `break`, `continue`, `return`.
*   **Свойства объекта:** `position`, `rotation` (градусы), `scale`, `color`, `visible`, `velocity`, `mass` и другие.
*   **Модули:** `input`, `scene`, `time`, `physics`, `audio`, математика.

Полный список функций и свойств всегда актуален в Script Editor: он строится из того, что движок реально умеет. Ошибка в скрипте останавливает только этот скрипт; бесконечный цикл редактор не вешает. Файлы перечитываются на лету, пока идёт игра.

```
SDF_Engine [scene.nos | mesh.obj] [опции]
  --project <dir>        папка проекта
  --demo                 открыть демо-сцену
  --export <dir>         собрать игру в папку и выйти
```

`NLSDFE_VALIDATION=1` включает слой валидации Vulkan.
